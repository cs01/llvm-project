that compile under `-fsafe-c` without `__unsafe` and then corrupt memory or crash
untrapped. Probes were kept under /private/tmp/claude-501/fable-probes/. Status is

## What the Lean core model says (safe-c-lean/, 2026-11-23)

A small core calculus of Safe C's rules with a machine-checked soundness theorem
(`SafeC.safe_c_sound`: a well-typed program with no `__unsafe` never reaches undefined
behavior; it finishes, traps or runs out of fuel). No `sorry`; only Lean's standard
axioms. The theorem holds only under three rule conditions, and each is necessary: a
counterexample program reaches UB when any one is weakened (`SafeC/Holes.lean`).

- **Hole 1 (zeroed nonnull slots):** the null trap now in the compiler is sound, but it
  must stay unconditional (checked: it survives -O2/-O3 on the review's probes).
- **Hole 2 (type confusion): the current rules are unsound.** Rule needed: a pointee
  cast is allowed only to `void`, between identical types, or between two pointer-free
  types, with nullability and bounds kind part of the type at every level below the
  top. Unions with pointer members fall under the same rule. To implement.
- **Hole 3 (narrowing across calls):** not exploitable while the null trap stands; for
  narrowing to mean something on its own, calls must drop narrowing facts.
- **Hole 4 (checked null-terminated conversion, then an alias erases the terminator):
  the current rule is unsound.** Rule needed: the converted pointer keeps the bound its
  scan found, and accesses through it are checked against that bound. To implement.

### Earlier the same day

- **Linux is not usable yet.** The compiler builds, and 130 of 132 tests passed on
  Ubuntu 24.04 (CI stopped there, so the standard library tests have not run). glibc's
  headers carry no bounds annotations, so a pointer a system function returns
  (`fopen`, `getenv`) cannot be used outside `__unsafe`. Plan: wrapper headers that
  re-declare the common functions with annotations.
- **Not sound.** Found and fixed today: a double free after `_Take` from a field; heap
  arrays of views; one argument stored through another (`*out = in`), which callers did
  not see, and `_Noescape` not checked against it; a global's owned pointer stored
  through a parameter or returned to another file. Hole 7 above is still open.
- **Found and closed: 53 accepted programs that AddressSanitizer flags**, plus a double free through
  a pointer to a null local (Juliet CWE415 variant 32) and one compiler crash. All are in
  `clang/utils/safe-c/holes` (`check.sh` counts what is left); the 13 causes are in
  [OUTARGS.md](../safe-c-lean/OUTARGS.md). Pointers to borrows held in locals or built
  by an expression (`p = &o; *p = b;`, `set(c ? &o : &o2, b)`) are now rejected, which
  closed 30 of the 55. Arguments to
  one call that overlap (`f(q, &s)` where `q` borrows `s`) are rejected too, which closed
  12 more, and the remaining 13 are rejected as
  of the same day. All programs in the corpus are either rejected or run clean. One
  rule has a real cost: a global that owns memory may not be passed by pointer to a call
  that may also reach it by name (another file's function, or one called through a
  pointer). `clang/utils/safe-c/holes` is the regression gate.
- **Found and closed the same day:** freeing or giving away something that is not a whole
  owned block, through a local pointer (`char a[8]; char *p = a; free(p);`), was never
  checked; and an `alloca` buffer could escape a function that ends without `return`.
- **The Juliet run-time numbers are being rechecked.** The harness subtracts traps the
  platform raises by itself (macOS malloc, for example) by rebuilding each case
  without Safe C, and that rebuild failed on ported files. 2,324 of the 5,545 were
  filtered properly; for 3,221 it is unknown whether any trap was the platform's (27 of 27
  rechecked were Safe C's own). The fixed harness records where the trap happened; a full
  rerun is under way. The compile-time numbers do not depend on it.
- **The Lean models do not cover** threads; the out-argument model covers one pointer
  level only (its limits are listed in OUTARGS.md).
